# BetSafe

Flutter phone app for virtual NFL picks and collectible rewards. Five-person student project. No login, deposits, cash-outs, or real-money purchases.

## What works in this foundation

Games → select a team and stake → submit to the Node server → start/finish a simulated game → view result → view earned team collectible. My picks shows pending and settled picks. Server validates stakes, duplicate picks, balance, and a 500-coin daily stake limit. A win returns 2× the stake including the original stake; this is a demo rule, not real betting odds. The home team wins each fixture so the video is repeatable.

**NFL schedule** shows real schedules/scores from BALLDONTLIE when a server API key is configured. **Demo games** is the separate, explicitly labeled simulation. All stakes and payouts remain virtual; no sportsbook odds are fetched. Player cards, persistent storage, and deployment remain team tasks. One shared in-memory demo account starts with 1,000 coins. All connected clients share it, and restarting the server resets it. Daily stake usage resets at midnight UTC. Do not expose the demo server publicly.

## Requirements

- Flutter 3.47.1 / Dart 3.13.1 (matches the generated project)
- Node.js 24 and npm
- Android Studio with an Android emulator; Mac + Xcode with an installed iPhone simulator for iOS

## Start the server

Open a terminal in this repository:

```sh
cd server
npm ci
npm start
```

Server: `http://127.0.0.1:3000`. Check `http://127.0.0.1:3000/health`. `npm run dev` restarts on code changes. Optional: copy `server/.env.example` to `server/.env` to change host/port. Secrets stay in ignored `.env` files.

## Start the app

In a second terminal at the repository root:

```sh
flutter pub get
flutter devices
flutter run -d <device-id>
```

Replace `<device-id>` with an ID from `flutter devices`. Start the emulator/simulator through Android Studio or Xcode first.

The default server address is `http://10.0.2.2:3000` on an Android emulator and `http://localhost:3000` on the iPhone simulator. Android localhost points to the emulator itself, which is why the addresses differ.

For a physical phone, put your Mac and phone on the same trusted Wi-Fi, set `HOST=0.0.0.0` in `server/.env`, restart the server, and use your Mac's local IP:

```sh
flutter run -d <device-id> --dart-define=API_BASE_URL=http://192.168.1.20:3000
```

Replace the example IP with your Mac's actual Wi-Fi IP. Accept the iPhone local-network prompt. Physical iPhone testing also needs an Xcode signing team. Android local HTTP is allowed only in debug builds; a release backend must use HTTPS. iOS allows local networking without disabling TLS certificate verification. Web/desktop targets were generated by Flutter but are not configured or verified for this MVP (the server has no browser CORS policy).

## Real NFL schedules and scores

Copy `server/.env.example` to `server/.env`, then set `BALLDONTLIE_API_KEY` only in the ignored `.env` file. Leave `.env.example` blank for teammates. Restart the server after changing the key. Verify access with `npm --prefix server run check:nfl`; this reports only connection status and game count, never the key.

The server queries one rolling date window (three days back through seven days ahead), caches it for 60 seconds, coalesces simultaneous refreshes and backs off on rate limits. The app refreshes once per minute while foregrounded and offers manual refresh. Source/fetch time and errors are shown; the fetch time does not guarantee the provider's own data freshness. No play-by-play feed is included.

Picks on real games close at kickoff and require fresh provider data. Final results settle pending picks once; ties/canceled/abandoned games return the stake. Settlement happens when state is refreshed, not through a background job. Postponed/delayed/suspended/unknown games accept no new picks and await a definitive result. Keep the server running for the demo: accounts, picks and settlement are still in memory and reset on restart. Real games cannot use the simulation advance route.

## One-command Android development

Start your emulator in Android Studio → Device Manager, then from the repository root:

```sh
npm run android
```

If more than one Android device is connected, choose one explicitly:

```sh
npm run android -- emulator-5554
```

The launcher finds the Android device, checks the local BetSafe server, starts it if needed, and launches Flutter with the emulator’s server address. It reads the server port without printing your API key. An existing server is reused and stays running; a server started by the launcher stops when you quit Flutter. Press `q` to quit or `r` to hot reload. Restart a reused server yourself after changing server code or .env.

For a physical Android phone, use the LAN setup above and set API_BASE_URL in your terminal before running this command; the emulator address will not work on a phone.

CI can also be started from GitHub Actions → Build and test → Run workflow after the updated workflow is pushed. New runs cancel older unfinished runs for the same branch/PR. Jobs time out after 25 minutes; successful build artifacts are retained for seven days.
